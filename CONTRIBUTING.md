# Contributing

Read `AGENTS.md` and `docs/PROJECT_CANON.md` first. Discuss product or architectural changes before implementation, record unresolved choices in `docs/OPEN_QUESTIONS.md`, and use an ADR for accepted architecture changes.

Use neutral, original terminology and data-driven content. Keep changes focused, add validation coverage, update affected documentation, and use Conventional Commits such as `feat:`, `fix:`, `docs:`, `test:`, or `chore:`. Pull requests must state scope, evidence, data/save compatibility, and any canon impact.

Do not submit unauthorized third-party IP, executable mods, secrets, generated caches, or claims unsupported by a run.
